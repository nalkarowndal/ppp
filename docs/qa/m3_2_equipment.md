# M3-2 장비·강화 시스템 검증

**기준:** Godot 4.7.2 / M3-1 Draft #18에서 분기 / 2026-11-12.

## 동작
- 장비 슬롯: 무기 1, 방어구 1, 장신구 2 (4개).
- 장비 카탈로그: data/equipment.json에 임시 6종, 장착 데이터는 고유 instance_id로 구분.
- COMMON/RARE/EPIC 강화 상한: +5/+10/+15. 강화 성공 확률은 100%이며 실패·파괴 없음.
- 장착·교체·해제: 단일 아이템의 두 슬롯 중복 장착, 다른 영웅이 이미 착용한 아이템 재장착 차단.
- 캐릭터 성장 수식 적용 후 장비 고정 증가량을 합산하고, 해당 능력치의 퍼센트 보너스를 더해 **1회만** 적용.
- 1강마다 장비 **고정 수치** 10% 상승(각 장비별 floor). 퍼센트 보너스는 강화로 증가하지 않음. SPD/CRIT/CRIT_DMG는 이번 프로토타입 장비에 의해 변경되지 않음.
- 골드 소비 = 100 × (현재 강화 레벨 + 1) × 등급 배수(일반1/희귀2/영웅4), 강화석 = 1 + floor(현재 강화 레벨 / 5). 모두 초기 밸런스 가설.

## 데이터 안전
- 모든 거래는 원본 loadout, inventory, wallet의 Dictionary에 직접 변경을 가하지 않음.
- 잘못된 아이템 ID, 타입, 비정상 강화 레벨, 슬롯 불일치, 장착 상태 불일치 거부.
- 보유 아이템의 instance_id는 고유하며 M3-3에서 획득·중복 발급을 관리할 예정.
- 결제/강화 실패 시 부분 차감 없음. 교체할 때 이전 장비는 제거하지 않고 보유 상태로 전환.

## CI 테스트
- tests/m3_equipment_test.gd: 교체/중복 장착/소유자 검사, 4슬롯 스탯, 능력치 적용 순서, +5 상한, 비용 원자성.
- 기존 tests/m3_growth_test.gd 및 M2-1~5, M1 Windows/Android Export 회귀 유지.
- scripts/validate_data.py에서 신규 장비 JSON 정적 검사 수행.
- Actions 결과는 최종 HEAD에서 직접 확인하고 합격 여부 기록.

## 구현하지 않은 범위
- M3-3 재화 지급·수령 멱등성, 장비 제작·드롭·판매.
- M3-4 8시간 방치, M3-5 영구 저장·복구·마이그레이션.
- M3-6 장비 UI, 정식 아트/아이콘, 장비 적용 전투 엔트리포인트와 실제 Android ARM64/Windows 물리 기기 QA.
- 장비 6종은 밸런스 테스트용 초기 데이터이며 정식 장비 도감이 아님.
- M1 물리 QA issue #2, main 병합 및 M3 전체 승인은 보류.
