# Astral Chronicle M2-5 Battle UI Integration Design — 2026-11-11

## Context
M2-1..4 deterministic 20Hz battle logic, targeting, 16 skill types, and statuses exist as standalone RefCounted data simulation. The main Godot scene (`scenes/main.tscn`, `scripts/ui/main_ui.gd`) still runs a legacy M1 sandbox with real CI tests that require its existing button texts and save/scroll behavior. The game window is mobile-portrait 360×800, stretch `canvas_items` with expand aspect. Main UI has system Korean font, no packaged sprites.

## Decision
Create a **separate optional battle preview scene** `scenes/battle_m2_5.tscn`, launched from a new button **after the legacy M1 save panel**. Leave M1 default scene and M1 QA control positions/IDs untouched. The preview is an actual interactive Godot Control UI driven by `AutoBattleCore`, but explicitly **development/provisional**, not final pixel art or production art. Maintain clarity at 360×800 and constrain layouts within a ScrollContainer for differing aspect ratios. Use theme colors from `docs/02_ui_ux/design_system.md`, programmatic Control/PanelContainer/ProgressBar, a clear status/skill label for Hangul and touch-sized buttons (min 48 logical px).

## Runtime contracts
- The battle UI loads `characters.json` / `enemies.json` / `skills.json` from Repo. Select first 3 playable heroes and first 3 enemies (repeat distinct templates with unique suffix IDs when roster only has 3). Configure the skill catalog **before** `setup`; fixed seeded encounter for reproducible QA.
- `_process(delta)` accumulates `min(delta, 0.1) × speed`, advances exactly 20 logical ticks/sec regardless of visual frame pacing; maximum 16 accumulated ticks per frame to avoid UI stalls; end states stop. Speed selector 1×→2×→3×→1× only changes logical advancement, not formulas. Preserve remaining fraction across frames.
- AUTO button toggles **automatic ultimate casting only**: active/basic remain automatic. Manual ultimate button per ally appears for three heroes; enabled only when manual mode, hero alive, energy ≥100, state running; pressing queues via `request_ultimate` and applies on the hero's next gauge-ready action. Explain that behavior with UI label.
- Display enemy/ally unit cards with name, row, HP progress and numbers, energy, active status labels (include stack and remaining seconds), and current result. Show actor action status, speed, recent combat log; highlight hit/heal/ultimate with low-intensity Control tween or flash in a distinct color, with a **reduce motion** toggle. No imported third-party art.
- Back button returns to M1 scene, restart creates a fresh deterministic battle, result state pauses UI; no M1 debug save operations are modified or M2 save persistence falsely claimed.
- Presenter function accepts a combat `snapshot()` and creates deterministic text models; read-only snapshots and no player stats/JSON mutation.
- New automated UI test instantiates actual scene, verifies all key controls and 3v3 binding, triggers speed/AUTO/ultimate/restart and M1 launcher, status updates, event log and labels. Tests run headless with Godot 4.7.2; no claims about real screenshot/visual QA based solely on headless tests.
- Optional CI visual capture using Linux Xvfb and real window renderer may be attempted; if images cannot be generated or checked, document the barrier transparently, do not mark visual QA done.
- Preserve all existing M1 and M2-1..4 regressions. Keep stacked Draft PR off main and Windows/physical Android ARM64 QA #2 pending.

## Non-goals
Final illustrated/pixel-art sprites, final VFX/audio/cutscenes, results/rewards persistence, 12-screen app navigation, profile, equipment, accessibility certification, direct real Windows GUI click testing or Android ARM64 touch/safe area screenshot. Those require actual hardware/sources and remain gated.
