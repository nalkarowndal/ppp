# M3-3 Economy and Receipt Design (2026-11-12)

Base: feature/m3-2-equipment-system. Head: feature/m3-3-economy-inventory-ledger.
Implement a pure deterministic economy state without modifying Godot M1 debug save or M2 battle UI.

A player has six prototype currency balances and an equipment inventory keyed by unique instance IDs. Every reward/spend/level-up/ascension/enhancement operation takes a stable event ID. A successful operation returns a complete immutable state snapshot with a permanently retained receipt. Duplicate/replayed IDs are rejected before changing state, regardless of request kind or payload. Failed operations do not mark a receipt. No platform time is consulted.

Claims mint individual inventory entries from validated M3-2 catalog templates, with collision checks and cap protection. Receipts survive in-memory JSON stringification and normalization; due to JSON float semantics integral currency counts and enhancement levels must be normalized before use.

Safety boundaries: trusted reward issuer is not built; client-side idempotency is not server-side anti-cheat. Atomic persistence/backup is M3-5; UI is M3-6; stage reward source is M4. Keep PR as Draft and avoid main merge pending QA.
