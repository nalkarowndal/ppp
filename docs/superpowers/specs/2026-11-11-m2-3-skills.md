# M2-3 Skill Execution Slice — 2026-11-11

## Chosen design
Build a data-driven skill runtime that reads the 16 supplied skill records via explicit `configure_skills(array)`; no implicit file I/O in combat. The same 20 Hz tick drives basic attacks, actives, ultimate readiness, cooldowns and deterministic RNG. Keep targeting/damage data independent of presentation and allow UI to queue an ultimate. Use an isolated stacked branch based on M2-2; keep M1/M2-1/2 pending Draft PRs and hardware gates.

## Behavior contracts
- `configure_skills(skills)` validates unique skill IDs and supported categories/targets, copies the input deeply, returns success bool, and never modifies original `data/skills.json`.
- Existing `setup(party, encounter, seed, is_boss)` API remains unchanged; a battle can run in legacy basic-only mode if no skill catalogue is configured.
- At action gauge readiness the actor tries: eligible ultimate (energy 100, auto mode or valid manual request) → ready ACTIVE → BASIC.
- `set_auto_ultimates(enabled)` defaults true. With false, `request_ultimate(team,id)` queues one manual use (only for a living unit with valid ult, avoids duplicate requests); consumed on that actor's next action if energy is 100. A manual request is allowed before energy reaches 100, but cannot bypass the requirement.
- `cooldown_sec` is converted to integer ticks via ceil(seconds * 20); cooldown begins at successful ACTIVE cast, no instant recast; cooldown 0 for ULTIMATE but energy fully spent.
- Damage skills use existing RNG and elemental formula. No new RNG for selection. Enemy-target skills target living units; row overrides for ENEMY_BACK; multi-target count cap 3; ALL means all living.
- Support heals capped to max HP, shield adds `shield` and consumes before HP in later attacks, self-taunt uses existing `apply_taunt` for 3-second provisional duration. Unlike M2-4, no burn, poison, freeze, slow, regen, def_down or stack/immune timers. Emit `deferred_effect` in cast event for those effects.
- `MULTIHIT_3` hits the same target three times; CHAIN targets at most three living enemies with base coefficient sequence 1.5/1.1/0.75 (GDD). Taunt does not force area skills to target a single enemy; it governs single-target selections.
- A successful skill emits `skill_cast` and optionally `skill_hit`, `heal`, `shield`, `taunt` events with tick/actor ID; all are capped at 64 recent events.
- Win/defeat/timeouts, replay, 1x/2x/3x, original source dictionaries and M1 debug flow stay consistent.

## Explicit exclusions
No combat UI, animation, save persistence, status stack/duration, passives, 5-person formation validation, full skill balance certification, actual Android/Windows device checks. Keep JSON `spec_only_not_implemented` until complete M2-4 effect fulfillment; the event layer is provisional. Existing Draft PR #12 and #13 remain untouched.
